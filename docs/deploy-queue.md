배포가 필요한 작업은 여기에 모았다가 12월 1일에 한 번에 배포한다.

## 대기 중
- 정보글 본문에서 품목 페이지 링크 지원: 예) `[품목:계란]` → "계란 최저가 모아보기" 링크
  (지금은 상품 카드 `[상품:ID]` 만 지원 — 품목 페이지로 내부 링크를 걸면 색인·상위노출에 도움)
- 가격 두 줄 표시 (쿠팡처럼): 와우가 / 일반가 — 11/7부터 option_price_history.source 로 API 별 가격을 모으는 중.
  며칠 뒤 같은 옵션의 search(와우가 추정) vs best·goldbox(일반가 추정) 가격을 비교해 확인한 뒤 구현
- 옵션별 가격 목록 + '여러 개 사면 얼마 절약' (product_options 에 11/7부터 수집 중)
- 단위 가격 표시 (상품명에서 개수·용량 읽어 1개당·100g당)
- 관리자 화면 상단에 수집 현황판: 24시간 안 가격 확인 비율, 오늘 확인한 상품 수, 소개글 있는 상품 수, 최근 갱신 상품
- 관리자 상품 목록에 '소개글 없는 상품만' 체크 (API 는 nodesc=1 로 이미 지원)
- 상품 구조화 데이터(서치콘솔 '판매자 목록' 경고 정리): `category` 는 빼거나 구글 형식으로, `offers.validFrom` 에 가격 확인일 추가.
  반품정책·배송정보는 우리가 판매자가 아니라 넣지 않음 (사실과 다른 정보 금지). gtin·브랜드는 API 에 없어 생략
- 상품 페이지에 '가격 확인일'이 오래된 경우 표시 (예: "3일 전 확인") — 재확인 작업과 함께 신뢰도 표시
- 판매종료 상품 숨기기: 11/9부터 재확인에서 사흘 연속 못 찾은 상품을 '판매종료 의심'으로 표시 중 (refresh_tries.misses ≥ 3 이고 tried_at > updated_at).
  - 홈·카테고리·키워드·검색 목록, 사이트맵에서 빼기
  - 상품 페이지는 남겨서 가격 기록은 보여주되 "판매 종료(또는 일시품절) — 마지막 확인 날짜" 안내 + noindex
  - 다시 잡히면 자동으로 원래대로 (수집 쪽은 이미 그렇게 동작)
  - 판매종료 페이지에 "지금 판매 중인 같은 상품" 후보 링크 (product_successors 테이블, 11/9부터 수집 중 — 모델명 일치·이름 70%·가격 ±30%, 상품당 최대 3개)
- (배포 없이 이미 적용, 11/9) 같은 상품번호에서 원래 판매자가 빠지면 같은 옵션의 새 판매자로 자동 전환 + 구매 링크 교체 (vendor_switches 에 기록)
